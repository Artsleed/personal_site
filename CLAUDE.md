# Project context for AI assistants

This file exists to hand off context to whichever AI assistant picks up work on this repo next. Read it before making changes — several of the notes below document real bugs that were hit and fixed, and the same mistakes are easy to reintroduce without this context.

## What this is

Nathaniel Felsky-Deelstra's personal site — portfolio, blog, resume, films, music. **Not** a clubs-and-projects org site despite the parent folder name (`clubs_and_projects/website/`) — the actual project lives in the `personal_site/` subfolder, which is its own git repo (`github.com/Artsleed/personal_site`).

Astro 6, no UI framework, plain CSS with custom properties (no Tailwind). Deployed on Vercel via `@astrojs/vercel`; pushing to `main` on GitHub triggers an auto-deploy — no manual deploy steps.

## The room (current design, since 2026-09)

The homepage is **an illustrated bedroom, not a conventional layout**. `src/components/RoomHome.astro` inlines a static SVG illustration (`src/assets/room/room.svg`, 1440×900) and overlays six clickable hotspots — corkboard, desk, posters, record player, bookshelf, framed page — each mapped to a site section (Projects, Writing, Films, On rotation, About, Resume) in `src/data/room-zones.ts`. Clicking one opens a card previewing that section (list of recent items, a stat, whatever's relevant) with a button through to the section's full page. The top-right nav row and the header's other-page links were deliberately removed elsewhere in the site — **the room is the only way to move between sections**; every inner page's only navigation back is a "← Back to the room" link in the header (`Layout.astro`).

This replaced an earlier "grand vision": a persistent three.js 3D room (`DeskScene.astro` → `Room.astro`) that spanned every page via `transition:persist`, camera-tweening between areas on navigation. That system got ~11 rounds of real polish (documented in git history if you need it) but was fully replaced by the current 2D illustrated version in September 2026, per the user's own direction — if you go looking for `Room.astro`, `DeskScene.astro`, or `now.astro`, they're gone on purpose, not missing by accident.

### How the room is built

- **`room.svg`** is hand-edited after being copied from its original design handoff (archived at `design/room-handoff/`, see that folder's own README for what's kept and why) — see the comment block at the top of `RoomHome.astro` for exactly what was changed and why, before ever regenerating or replacing this file.
- **Hotspots, labels, arrows**: positioned with hardcoded pixel coordinates in the 1440×900 artboard space (measured directly off the rendered SVG, not guessed). `.stage` is scaled to fit the viewport via a JS-computed `transform: scale()` (see `fit()` in the component's script), not CSS `object-fit` — this keeps every hardcoded pixel coordinate correct at any window size.
- **Zone cards**: each of the 6 `<section class="zone" data-zone="...">` blocks is shaped/sized differently per its object (`data-shape` attribute — cork strip, desk bezel, picture frame, cabinet wood-grain, bookshelf spine, thin frame + glow) rather than one generic box, on request. Open/close/hash-deep-link/focus-management logic is plain vanilla JS in the component's own `<script>` — see the "Click/keydown are bound once per real browser session" comment there for why listeners are bound at module scope, not inside `astro:page-load`.
- **`bare` prop on `Layout.astro`**: the room needs to own the entire viewport (its header/nav are baked into the 1440×900 stage, not `Layout`'s normal chrome). Pages that pass `bare` get no header/footer from `Layout` and `main` loses its padding/width cap. Only `index.astro` uses this.

### Real gotchas hit building this (worth reading before touching the room again)

1. **`mix-blend-mode` + a CSS `transform: scale()` ancestor = a real Chromium compositor bug.** The lamp's warm glow and the resume picture-light originally used `mix-blend-mode: screen` (as authored in the source SVG). At the stage's native 1440×900 size this looked fine, but at *any other* window size — i.e. almost every real one, since `.stage` is scaled to fit — a soft rectangular seam appeared over the lamp shade and the curtain behind it. Root cause: Chromium rasterizes a blend-mode layer as its own compositing surface, and that surface's bounding-box edges become visible once the whole thing is scaled. Fixed by stripping `mix-blend-mode` from the SVG entirely (plain alpha-blended glow reads fine without it). **If you ever see a soft rectangular seam/smudge in the room at some window sizes but not others, suspect this exact interaction before anything else** — it reproduces at scaled sizes and disappears at exactly 1440×900, which makes it easy to miss if you only test at the "clean" size.
2. **A stray orphan `<g>` was sitting right next to the lamp's real group in the source SVG** — a small second shade-cap shape at a different scale/skew than the actual lamp, overlapping the curtain. Found by user report ("weird after-effect on the shade"), confirmed as a genuine orphan (not load-bearing for the shade's silhouette) by toggling its `display:none` first and checking no gap was left behind, then deleted from source. If a shape in the room looks like a disconnected duplicate of something else, check for this pattern before assuming it's a rendering bug.
3. **`object-fit: cover` cannot show a poster's full width and full height at once inside a frame narrower than the poster's own aspect ratio** — and no amount of resizing the *box* changes that (cover's scale is always set by whichever dimension is more constraining, independent of how wide or tall you make the box otherwise). The room's two poster frames are much narrower than a real poster's ~2:3 ratio, so the two frame `<img>`s use `object-fit: fill` (stretch, no crop) instead — guarantees the full title is always visible on any film, at the cost of a slight, barely-noticeable squeeze at this size. `clip-path` (measured off the frame's actual tilted corners) is what makes the image follow the frame's true perspective tilt, separately from the fit-mode question.
4. **A plain `@import` inside a component's scoped `<style>` block silently 404s on relative asset paths** — confirmed with `@fontsource` CSS, which references its own `.woff`/`.woff2` files by relative URL. The identical `@import` syntax works fine in `global.css` (a real top-level Vite-resolved module), but not inside an Astro component's inline `<style>`. Fix: import font CSS from the component's frontmatter script (`import '@fontsource/x/400.css';`) instead of via `@import` in the style block.
5. **Astro's scoped-style specificity collision — this is a recurring bug pattern in this codebase, not a one-off.** Astro auto-appends a `data-astro-cid-*` attribute selector to every rule in a page's own local `<style>` block. A bare element selector there (`p { color: ... }`, `h2 { font-weight: 500 }`) has *higher* specificity once scoped than a plain global class rule (`.kicker { color: ... }`), because an attribute selector counts like a class. This silently broke the site-wide `.kicker` accent color on `projects.astro` and `blog.astro` (each had its own local `p {}`/`h2 {}` meant only for card text, which happened to also match the page's kicker `<p>`) — and it's bitten this project before, per earlier history. **If a shared class's color/weight/font looks right in its own CSS but wrong on one specific page, check that page's own scoped styles for a same-tag-name rule before assuming the shared rule is broken.** Fix is always to scope the local rule to its actual intended context (`.project p` not `p`), never to touch the shared rule.

## Design system

Tokens live in `src/styles/global.css`, shared across the room and every other page — the whole site reads as one continuous place, not a themed homepage dropped onto an unrelated rest-of-site.

- `--color-bg: #0d1217`, `--color-accent: #ee8a45` (warm orange, matches the room's lamp glow) — the one accent, used sparingly.
- Three font roles: `--font-serif` (Instrument Serif — display only: names, page titles, card titles; **ships only a 400 weight**, never ask for 500/600 or you'll get a synthetic-bold fallback), `--font-sans` (Hanken Grotesk — body/UI/labels; `--font-mono` is aliased to this same stack on purpose, there's no separate monospace face anymore), `--font-script` (Caveat — handwritten accents: kickers, the room's labels, card eyebrows, the "back to the room" link, `.aside` reveal-on-hover asides).
- `.kicker` is now a Caveat-script eyebrow in accent color (no more `// ` mono-comment prefix) — same voice as the room's card eyebrows ("the corkboard" above "Projects"), so a page reads as the same object you just opened from the room.
- `.ticked` (the old drafting-sheet corner-tick-mark device) is a deliberate no-op now — kept as a class so `Panel.astro`/`SpecHeader.astro`/existing markup that still applies it doesn't need editing, but it draws nothing. The room's own "considered object" language is just a rounded, bordered panel (`--radius: 12px`).
- `.tilt` (hover-lean), `.aside`/`.aside-trigger` (reveal-on-hover handwritten note), `.full-bleed` (viewport-width breakout, see the layout gotcha below) all carry over unchanged.
- **`main` is left-justified and capped at `--page-width` (1120px), not centered** — `.full-bleed` (`width: 100vw; margin-left: calc(-1 * var(--space-5))`) exists specifically because the naive `left: 50%; margin-left: -50vw` full-bleed trick assumes a centered parent and silently breaks here. Confirmed broken twice historically before this became the standard pattern.
- **`overflow-x: hidden` on `html`/`body` breaks the sticky header's `position: sticky`** (a real CSS interaction: non-visible overflow changes the containing block used for sticky positioning). Fix overflow issues at their source, not with a blanket overflow hack.

## Live data

- **Films**: `src/lib/letterboxd.ts` fetches and parses Nathaniel's Letterboxd RSS feed (title, year, rating, watched date, rewatch flag, poster URL — real XML entity decoding included, the feed sends `&amp;`/`&#039;` etc. as literal text and a naive regex-based extractor will pass that straight through as visible page text if you don't decode it). Used by `src/pages/api/letterboxd.ts` (fetched client-side by the room, for the two frame posters + the Films card's grid) and directly by `films.astro` (server-rendered per visit, no HTTP round-trip to its own API route). Posters are plain CDN URLs (`a.ltrbxd.com` allows direct hotlinking, confirmed) — no server-side proxying/base64 needed, unlike an earlier three.js-era version of this code that had to work around a WebGL canvas-texture CORS restriction that no longer applies to plain `<img>` tags.
- **On rotation**: `src/lib/spotify.ts` does the refresh-token → access-token → currently-playing (falling back to recently-played) dance. Needs `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `SPOTIFY_REFRESH_TOKEN` as env vars (`.env` locally, Vercel project settings in production — `scripts/spotify-auth.mjs` is the one-off local OAuth flow to mint a fresh refresh token if needed). Used by `src/pages/api/now-playing.ts` (client-side, room's On Rotation card — refreshed on page load *and* again every time that specific card opens, since unlike the rest of the room's data this one goes stale within minutes) and directly by `music.astro` (server-rendered per visit).

## Other things worth knowing

- **`astro:page-load`, not top-level script code, for anything that does real work.** `<ClientRouter />` (in `Layout.astro`) swaps page content on internal navigation without re-executing already-loaded scripts — top-level module code in any component only runs once per real browser session. `RoomHome.astro`'s own script is the clearest example in the codebase: `fit()` (viewport scaling), `openFromHash()`, `loadPosters()`, and `loadNowPlaying()` all re-run on every `astro:page-load`, while the click/keydown delegated listeners are bound once at module scope (they re-query the DOM on every event rather than closing over stale references, so a single binding stays correct across navigation without stacking duplicates).
- **`[hidden]` vs. a component's own `display:` rule.** Any element you toggle with the `hidden` attribute needs an explicit `[hidden] { display: none }` override *if* you've also given that same selector an unconditional `display` value elsewhere (flex, grid, etc.) — the two rules have equal specificity, and yours (later in source) wins over the browser's default `[hidden]` behavior. `.zone[hidden]` in `RoomHome.astro` has this override with a comment explaining why; this exact bug class has recurred multiple times in this project's history.
- **Screenshot false positives**: `[data-reveal]` elements below the fold won't show as visible in a full-page screenshot even with a generous wait — the resize-and-capture doesn't reliably give the scroll-reveal `IntersectionObserver` time to fire. Don't treat that as a real bug on its own. Vite's `504 Outdated Optimize Dep` console errors right after a dev-server (re)start are also transient noise, not app bugs.
- **This project lives inside a OneDrive-synced folder**, which has caused real dev-server problems before (file-lock `EPERM` errors, orphaned `astro dev` processes piling up across a long session). Before starting a new `npm run dev`, kill stray node processes first (`Get-Process node | Stop-Process -Force` in PowerShell — Git Bash's `ps`/`pkill` report unreliable PIDs for native Windows processes here).
- **No `Co-Authored-By: Claude` trailer on commits for this project** — the user explicitly rejected a commit that included one.
