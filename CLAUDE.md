# Project context for AI assistants

This file exists to hand off context to whichever AI assistant picks up work on this repo next. Read it before making changes — several of the notes below document real bugs that were hit and fixed, and the same mistakes are easy to reintroduce without this context.

## What this is

Nathaniel Felsky-Deelstra's personal site — portfolio, blog, resume, "now" page. **Not** a clubs-and-projects org site despite the parent folder name (`clubs_and_projects/website/`) — the actual project lives in the `personal_site/` subfolder.

Astro 6, no UI framework, plain CSS with custom properties (no Tailwind). Deployed on Vercel via `@astrojs/vercel`; pushing to `main` on GitHub (`github.com/Artsleed/personal_site`) triggers an auto-deploy — no manual deploy steps.

## Design system (as of 2026-08-21): "spec sheet with a handwritten margin"

Replaced the old "Terminal/HUD" look (JetBrains Mono everywhere, terminal-window title bars, blinking cursor, scanline background) because the user felt it read as stuffy/corporate rather than personal. The new direction — studio/craft backbone, kinetic-minimal restraint, editorial pacing for long-form writing — is built around **personality on hover, not upfront decoration**: a recruiter scanning quickly sees a clean, rigorous page; someone who lingers finds a handwritten, personal layer underneath. Still dark-only, still built around a single warm accent — same idea as before, different execution. Full brief context lives in project memory (`project_personal_site.md` / `feedback_design_direction.md`) if you need the reasoning, not just the result.

Key tokens in `src/styles/global.css`:
- `--color-bg: #161514` — cool neutral near-black, deliberately not blue-leaning (avoid tech-brand navy) or brown-leaning (avoid looking like an existing brand palette)
- `--color-accent: #e0672e` — the **only** accent color now (blue/`--color-secondary` was dropped entirely in this redesign — don't reintroduce it without checking with the user first). Used sparingly: labels, hover borders, corner ticks, the primary button, handwritten asides. Never as a large fill or body text color, and don't stack more than ~3 uses of it in one view or it stops reading as an accent.
- `--color-heading` / `--color-body` / `--color-text-muted` / `--color-label` — text hierarchy, warm off-white down to a muted mono-label gray
- Four font roles, each with a specific job — don't blur them:
  - `--font-serif` (Fraunces) — display moments only: your name, page `h1`s. This is what gives the site a "human, considered" first impression.
  - `--font-sans` (IBM Plex Sans) — body copy, nav, UI. Reads as engineering-precise.
  - `--font-mono` (IBM Plex Mono) — labels/annotations only: kickers, spec-sheet metadata (stack/status/role/dates), never body prose.
  - `--font-script` (Shantell Sans) — the handwritten personal-aside mechanism only (see `.aside` below). If this font shows up anywhere else, it stops feeling personal and starts feeling like a font choice — keep it contained.
- `--page-width: 1120px` — see "full-bleed" section below, this does **not** mean pages are 1120px wide
- `--space-1` through `--space-5` spacing scale (unchanged from before)

Recurring visual patterns (all in `global.css` as shared classes — reuse them, don't re-implement):
- `.kicker` — small uppercase eyebrow label with a `// ` prefix in the accent color
- `.page-title` — the `h1` on every page (serif now, not mono)
- `.section-heading` — small uppercase mono label, no more left accent border
- `.ticked` — corner tick marks (drafting-sheet crop-mark device) on bordered containers; add alongside a bordered card/panel to signal "considered object." Keep it subtle — felt, not noticed on first glance.
- `.tilt` — the one hover interaction language for clickable cards (slight 3D lean + lift). Reused everywhere rather than a different hover effect per page — that consistency is the point.
- `.aside-trigger` + `.aside` — the reveal-on-hover personality mechanism: wrap a container in `.aside-trigger`, put the handwritten aside inside as `<span>`/`<p class="aside">`, and it's hidden until hover/focus. This is the site's core personality device (About's section notes and interest facts, project title asides, 404/500 jokes). Don't invent a second hover mechanism for the same purpose — reuse this one.
- `.spec-label` / `.spec-value` — small-caps mono metadata pairs, used by `SpecHeader.astro`
- `Panel.astro` — bordered, corner-ticked container, the general-purpose replacement for the old `TerminalWindow.astro` chrome (now deleted — nothing uses it anymore). Pass `tilt` for clickable cards.
- `SpecHeader.astro` — the 4-cell stack/status/role/started strip on project detail pages, backed by optional `stack`/`status`/`role`/`started`/`processNote`/`aside` fields on the `projects` collection schema (all have defaults, so older placeholder entries without them still validate).

**Now page, take 2 - real 3D via three.js (2026-08-22):** the flat CSS record-player/TV-set version above was superseded same-day - the user wanted genuine 3D (not a CSS illusion), envisioning a desk with a note in the middle and the TV/record player sitting on it. Built as `DeskScene.astro`: one component owns the whole scene (procedural three.js geometry - no sourced 3D models, no orbit controls, static camera only for now) plus its own data fetching. Key points for whoever touches this next:
- **Progressive enhancement, and it matters for bundle size, not just accessibility.** `three` (~718KB) is only ever pulled in via a dynamic `import('three')` gated behind a `hasWebGL()` feature check, so the cost is zero for anyone without WebGL - they get a plain-text fallback panel (`#desk-fallback`) with the same prev/next film cycling, and there's also an `aria-live` `sr-only` summary kept in sync for screen readers regardless of which path renders (canvas content is otherwise entirely inaccessible).
- **`hasWebGL()`'s throwaway probe canvas must explicitly call `loseContext()`** on the context it creates to test support. Without that, every navigation back to `/now` leaks one more WebGL context toward the browser's (low, especially under headless/software rendering) global context limit; leak enough of them and `hasWebGL()` starts returning `false` on a machine that actually supports WebGL, silently flipping real visitors into the text fallback. Caused a real, reproducible bug during testing (fallback panel stuck visible under the canvas after ~3 client-side navigations) before this fix.
- **Cleanup is triggered by `astro:before-swap`, not just by polling `canvas.isConnected` in the render loop.** The `isConnected` check is kept as a backstop, but the primary guarantee that at most one `WebGLRenderer`/GL context is ever alive comes from disposing the active scene (`renderer.dispose()` + `renderer.forceContextLoss()`) proactively right before Astro's `ClientRouter` swaps the page out - relying on the render loop alone to notice disconnection is timing-dependent and was the second half of the leak above.
- **Letterboxd poster images are proxied server-side, not fetched directly from the browser.** `src/pages/api/letterboxd.ts` fetches the RSS feed itself (regex-extracts title/link/poster-`<img>`-src per `<item>`, no DOM parser available server-side) and re-serves each poster as a base64 `data:` URI. This exists because `a.ltrbxd.com` sends no CORS headers - loading its images directly into a canvas/WebGL texture from the browser throws a CORS error and the texture silently stays blank. This also replaces the old client-side `rss2json.com` dependency entirely.
- Colors for the scene's materials are read at runtime from the same CSS custom properties as the rest of the site (`getComputedStyle(document.documentElement)`), not hardcoded a second time, so the 3D scene can't silently drift from `global.css`'s palette.
- Deliberately scoped out for now, and worth reconsidering later: camera movement (cursor/scroll parallax) and staging more of "the room" beyond the desk slab - both discussed with the user and intentionally deferred, not forgotten.

**Now page, take 3 - full-bleed layout + a model detail pass (2026-08-22, same day):** the first 3D pass rendered inside a bordered "window" card (like `Panel.astro`) at a capped 480px height - user clarified they wanted the scene itself to *be* the page, not sit in a preview box, plus more detailed models. Two changes:
- **Layout:** `.desk-scene` lost its border/background/padding entirely (the canvas's own `scene.background` already matches `--color-bg`, so it blends into the page with no visible seam), and sits in a `.full-bleed` wrapper in `now.astro` with no padding-inline (unlike every other `.full-bleed` usage on the site, which pairs it with `padding-inline` to keep content edge-aligned - here the point is the opposite, the canvas should touch the true viewport edge). Canvas height is `min(78vh, 900px)` instead of a 16:9-capped box. At this point the kicker/title still stayed in normal flow above the scene (not overlaid) - **superseded by take 4 below**, keeping this line only so the history of *why* makes sense.
- **A wider aspect ratio broke the fixed camera position** - on a narrow/portrait viewport the horizontal FOV shrinks (vertical FOV is fixed on `PerspectiveCamera`) while the desk/TV/record's world-space positions don't move, so the TV fell completely outside the frame on mobile. Fixed in `resize()`: the camera now dollies back along its fixed viewing direction as `aspect` drops below a tuned reference (`baseAspect = 1.5`), which keeps the full desk width in frame at any viewport shape instead of hardcoding one camera position. If you ever change `deskWidth` or the TV/record x-offsets, re-check both a wide (laptop) and narrow (phone-portrait) viewport - this is the kind of bug that only shows up at one aspect ratio and looks perfectly fine at another.
- **Detail pass** (all still procedural geometry, no sourced models): desk got a canvas-generated wood-grain texture (mapped only onto the top face via a per-face material array on the `BoxGeometry`) plus a front edge-banding strip; a plain back `wall` plane was added behind the desk so the space above it reads as a room rather than empty flat color. TV gained two feet (instead of one center riser), a recessed screen border baked into the screen canvas texture, and a power-light dot. Record player gained a felt mat ring, a metallic platter rim (`TorusGeometry`), plinth control buttons, and the tonearm went from a plain sphere tip to a proper headshell + stylus + counterweight. When stacking thin disc-like meshes on top of each other (platter → felt mat → record), leave an explicit gap between each layer's top/bottom y-coordinates - two layers sharing the exact same y silently z-fight/overlap.

**Now page, take 4 - kicker/title overlaid on the wall, a functional remote, more props, legibility fixes (2026-08-22, same day again):** a punch list from the user after seeing take 3. All in `DeskScene.astro` unless noted.
- **The scene now extends up flush against the header bar, with the kicker/title overlaid on top of it** (this is the "superseded" note above). In `now.astro`: `.scene-breakout` gets `margin-top: calc(-1 * var(--space-4))` to cancel `main`'s own top padding and pull the canvas flush against the sticky header; `.now-heading` (wrapping the kicker + `h1`) is `position: absolute; top: var(--space-4)` with `z-index: 2` so it paints over the now-overlapping canvas, plus a subtle `text-shadow` for legibility against the wall texture. `.now` itself needs `position: relative` for that absolute positioning to anchor correctly.
- **Album art now covers almost the entire record face** (like a picture disc) instead of a small center label - `paintRecord()`'s `labelR` went from `size * 0.2` to `size * 0.455`, and the concentric-groove rings were cut down to just a couple near the very outer rim.
- **A working 3D remote, not just a decorative prop.** Three button meshes (`prevBtn`/`nextBtn`/`powerBtn`) are tagged with `userData.action` and checked against a `THREE.Raycaster` on the canvas's own `click`/`pointermove` listeners (`pickRemoteButton()` unprojects the pointer through `camera` and intersects only that small button array, not the whole scene, so it's cheap). `stepFilm(delta)` and `togglePower()` are the single source of truth for that behavior - the HTML prev/next/power buttons below the canvas call the *exact same functions*, so keyboard/screen-reader users get identical functionality, not a degraded substitute. Power-off forces the screen texture to solid black and makes `stepFilm` a no-op until powered back on; the non-WebGL text fallback got its own independent (simpler) power toggle for parity. Canvas listeners are removed in `dispose()` alongside everything else.
- **A green banker's lamp** was added (brass base/pole/joint, a `ConeGeometry` shade, a `PointLight` under it for a warm glow). Gotcha worth remembering: `ConeGeometry`'s apex is at local `+Y` and its open base circle at local `-Y` - with **zero rotation** it already hangs pointing straight down like a real lampshade, so it only needed a small `-0.35` rad tilt, not the large rotation that seemed intuitive at first (a big rotation flips it to face away from the camera instead). **Shade geometry was replaced with `LatheGeometry` in take 5 below** - see that entry, this note is kept only so the apex/base orientation lesson still makes sense.
- **The note was propped up like a table-tent card for one round, then reverted to flat** (user didn't like the tilted look) - see take 5 below for the current flat pose. Keeping this for the rotation-sign lesson: `note.rotation.x = 0.8` (positive) tilts the *near* edge (toward the camera) down while the *far* edge lifts up and back, pointing the face normal up-and-toward the camera; the sign backwards makes the face point away and the note renders as a barely-visible thin line. If a flat plane goes invisible/thin-line after adding rotation, flip the sign, don't add more rotation.
- **The desk needed legs to stop reading as a floating plank** - two bugs found by testing, not by inspection: (1) the desk is deliberately *wider than the camera's frame* (so the wood reaches both viewport edges), so legs placed at the desk's true geometric corners land completely outside the visible frustum and never render at all - they have to sit under the *visually apparent* desk area (`legInsetX = 1.9`) instead of the real desk edge. (2) the desk's own bulk occludes anything set back from the front edge at this camera angle, so the *back* legs are essentially always invisible (fine, expected) but the *front* legs must sit almost flush with the front edge (`legFrontZ = deskDepth/2 - 0.1`) or the desk's own overhang hides them too. Both looked like "nothing rendered" and needed an actual screenshot to diagnose - don't assume a positioning bug is a code bug without looking.
- Moving objects around this scene is genuinely iterative - the lamp needed repositioning twice after being hidden behind other objects sharing its x-position (first behind the note, then still half-behind it); when adding a new prop, screenshot-check it specifically rather than trusting the position math alone.

**Now page, take 5 - room cohesion + model quality pass (2026-08-22, still the same day):** user wanted it to read as an actual room (not a desk floating in a void), disliked the tented note, and asked for better TV/lamp/record-player models. All in `DeskScene.astro` unless noted.
- **A real floor plane** was added (large `PlaneGeometry`, rotated flat, wood-plank canvas texture, positioned to touch the front legs' bottoms) alongside the existing back `wall`, so the room has both a ceiling-height wall and a floor instead of the desk appearing to float in flat color.
- **The sitewide blueprint-grid background (`body::before` in `global.css`) is now scoped off this page.** `Layout.astro` takes an optional `hideGrid` prop that adds a `no-grid` class to `<body>`; `global.css` has `body.no-grid main { background: var(--color-bg); }`, which makes `main` opaque and blocks the fixed grid layer from showing through anywhere inside it, while `header`/`footer` (outside `main`, with their own semi-transparent backgrounds) keep showing the grid as before. `now.astro` passes `hideGrid` to `Layout`. If another page ever wants this same "self-contained room" look, reuse the same prop rather than re-deriving a way to hide the grid.
- **The note reverted to lying flat** (the take-4 tent pose looked odd to the user) - legibility now comes entirely from a bigger/bolder/darker canvas-drawn font (`bold 52px`, ink color `#1c140c`) rather than the angle.
- **Lamp shade rebuilt with `LatheGeometry`** for an actual dome/bell curve (wide rim at the bottom tapering to a narrow top opening) instead of a plain cone - much closer to a real banker's-lamp silhouette. Note the coordinate convention is different from `ConeGeometry`: a Lathe profile's *first point* becomes the mesh's local origin, so here the **wide bottom rim** sits at `shade.position`, not the vertical center - anything positioned "relative to the shade" (the rim torus, the bulb glow, the pull chain) had to be recomputed against that when the shade was rebuilt.
- **TV rebuilt**: single center stand (a short neck + flat foot) replacing the old two-box feet, bezel depth cut from `0.12` to `0.06`, and a thin lighter "frame lip" baked right at the screen's edge for a slim-modern-panel look instead of the previous thick two-tone frame. All the screen/power-light/brand-mark z-offsets had to shift inward to match the shallower bezel depth - if you resize `tvBezel` again, every child mesh anchored to its front face needs re-checking, not just the ones you meant to change.
- **Record player rebuilt as a suitcase-style console**: a wood-finish `caseCase` (reusing the same `makeWoodTexture()` the desk uses, applied via a per-face material array so only the front face shows wood grain) replaces the old thin dark plinth, with a perforated-dot-texture speaker grille set into the front face and a `lidPivot` group that hinges the lid open from the case's back-top edge. The lid's visible face when propped open is whichever face was the **underside** when closed, not the top - physically, swinging a back-hinged lid up rotates what used to face down into facing the viewer. Getting this backwards means the visible face renders as a plain color with no wood grain. The prop-open angle (`lidPivot.rotation.x`) was tuned down from a near-vertical `-1.72` to `-1.3` after the lid read as an oversized, disconnected wall panel at the steeper angle - less than "fully open" reads better here. All platter/record/tonearm vertical offsets are now expressed relative to a `caseTop` constant rather than hardcoded numbers, specifically so the whole turntable assembly can shift as a block if the case height changes again.
- **`.tv-controls` (prev/power/next) moved from normal document flow to an absolute overlay** near the bottom of the now much-taller canvas (`min(94vh, 1100px)`, up from `min(78vh, 900px)`), instead of sitting in a separate section below it - keeps the room filling the page edge-to-edge down to the footer rather than leaving a plain gap for the controls to live in.

**Now page, take 6 - load-time fix (2026-08-22, still the same day):** user reported the page felt slow to load. Two real, measured causes, plus one perceived-performance fix:
- **`/api/letterboxd` used to base64-encode all 5 Letterboxd posters into one response (~356KB), when only the first (currently-displayed) film is ever needed immediately.** Cut to eagerly encoding just film `[0]` (`EAGER_COUNT = 1`); the other four now carry a `sourceUrl` (the original CDN url) instead of a `thumb`. Response dropped to ~73KB - confirmed by measuring both versions directly (`curl -s -o /dev/null -w '%{size_download}'`), not guessed.
- **New `src/pages/api/poster.ts`** fetches+re-encodes a single poster on demand, given a `?url=` query param - called lazily from `DeskScene.astro`'s `resolveFilmThumb()` the first time the user actually cycles to a film that wasn't eagerly loaded, then cached in an in-memory `Map` keyed by url so re-visiting a film never re-fetches. **This endpoint validates the hostname against an allowlist (`a.ltrbxd.com`) before fetching** - without that check it would be an open SSRF-style proxy (fetch-and-return-arbitrary-url-as-base64 is a real vulnerability class, not just a style nitpick). If you ever add another lazily-proxied resource, allowlist its host the same way; don't accept an arbitrary caller-supplied URL to fetch server-side.
- A `renderToken` counter guards `renderFilm()`/`resolveFilmThumb()` against a race where the user clicks prev/next again before a slow poster fetch resolves - the stale response is dropped instead of overwriting a newer film's screen.
- **Added a loading indicator** (`#desk-loading`, a small spinner + "Loading room…") shown until the very first `renderer.render()` call in `tick()`, since three.js itself (~718KB) is the single biggest remaining load-time cost and there's no getting around downloading it - the fix here is about not looking stalled/broken while that download happens, not about making it smaller. **Hit the exact same `[hidden]`-attribute-vs-`display:flex`-override bug a third time** building this (`.fallback` and `.tv-controls` had the identical bug earlier in this file's history) - `.scene-loading` needed `display: none` by default with a `:not([hidden])` override, not `display: flex` outright. Any new conditionally-shown element in this component should be checked against this pattern before assuming a `hidden` toggle isn't working.

**Environment note - dev-server pileup on OneDrive (2026-08-22):** the "several minutes to load" report right after the fix above turned out to be unrelated to the app - over 30 orphaned `astro dev` processes had accumulated across one long session (each restart spawned a new one without killing the old), several burning thousands of CPU-seconds, on top of a OneDrive process that had ~4.7 hours of accumulated CPU time from repeatedly re-syncing `node_modules`/`.astro`/`.vite` after every cache clear. This project lives inside a OneDrive-synced folder, which is *also* what caused the separate `EPERM: rename .astro/content-assets.mjs.tmp` errors seen earlier the same day - Node projects generate huge numbers of small files that sync clients handle badly. If dev-server behavior seems inexplicably slow or flaky again, check for both of these before assuming it's a code problem: `Get-Process node | Stop-Process -Force` (PowerShell; Git Bash's `ps`/`pkill` report different, unreliable PIDs for native Windows processes) to clear stray servers, and consider that OneDrive sync contention may still be settling even after that.

**Now page, take 7 - a punch list after seeing take 6 live (2026-08-22, still the same day):**
- **The TV was cropping movie posters to a random zoomed-in sliver.** `setScreenImage`'s image draw used `Math.max(...)` (cover-fit) to size the poster onto the landscape screen canvas; movie posters are portrait (~2:3), so covering a landscape frame means scaling up until only a thin strip of the image remains visible. Switched to `Math.min(...)` (contain-fit, letterboxed) so the whole poster shows. **Superseded by take 8 below** - contain-fit then looked too small/pillarboxed; the current version is a deliberate blend, not either extreme.
- **The note's front edge extended past the desk's own front edge into open air** - moved it back (`z: 0.5`, down from `0.95`) and shrunk it slightly (`0.98 × 1.3`, down from `1.2 × 1.6`) so it sits fully on the surface with margin.
- **Small rotation offsets added to `tvGroup`, `rpGroup`, and `lampGroup`** (a few hundredths of a radian each) so the desk doesn't read as a perfectly axis-aligned museum diorama - a deliberate "just set down" imprecision.
- **Record player, three changes reflecting real suitcase-player design:** (1) the small circular grille inset was replaced with a full-front perforated-texture material spanning the entire front face (with a thin wood-toned frame baked into the same texture) - real units use the whole front panel as the speaker, not a token circle. (2) Four small rubber feet were added under the case, which required lifting the whole case up by `feetHeight` and folding that into the `caseTop` constant so every part of the turntable mechanism (already expressed relative to `caseTop`) shifted correctly without touching each one - and, same lesson as the desk legs, the *front* feet needed to sit almost flush with the case's front edge (not inset like the back ones) or the case's own front face occludes them. (3) The lid material changed from opaque wood to a transparent `MeshPhysicalMaterial` (`opacity: 0.32`, `side: THREE.DoubleSide`) for a glass/smoked-plastic dust-cover look - it no longer casts a shadow (`castShadow` removed), since three.js shadow maps don't account for material transparency and an opaque shadow from a "glass" object would look wrong.

**Now page, take 8 - TV poster fill + on-screen title/rating caption (2026-08-22, still the same day):** user wanted the poster bigger on screen and the title/rating visible on the TV itself, not just below it. **Fully superseded by take 9 below** (`setScreenImage`/`drawCaption` no longer exist - replaced by `drawColumn`/`drawCaptionBox`/`renderScreenPair`) - kept only because take 9's blend-scale formula and the "rating is already bundled into the title string" fact both originate here.
- The scale was a deliberate blend, not pure contain or pure cover: `Math.min(containScale * 1.45, coverScale)` - a 45% zoom past pure contain, capped so it never exceeds full cover-crop. Pure contain read as small/heavily pillarboxed; pure cover crops so hard only an unrecognizable sliver shows (that exact bug shipped once already, see the take-6 entry above). The `1.45` multiplier is a hand-picked compromise, not derived from anything.
- Letterboxd's RSS feed already bundles the star rating into the title string itself (`"Inception, 2010 - ★★★★★"`) - no new data was needed to caption the screen, just reusing the string already shown in the HTML control strip below the canvas.

**Now page, take 9 - two posters side by side, not one (2026-08-22, still the same day):** user asked to show the last 2 watched films side by side filling the screen, each with its own legible title/rating.
- **`DeskScene.astro`'s screen-drawing code was restructured around `drawColumn(film, x, y, w, h, token)`** - draws one film's poster (top) and its own caption (bottom) into an arbitrary rectangle, so the same function serves either half of a split screen. `renderScreenPair(leftFilm, rightFilm, token)` calls it twice (or once, full-width, if only one film exists) with a `margin`/`gap` layout; `renderFilm()` now computes `leftFilm = films[filmIndex]`, `rightFilm = films[(filmIndex + 1) % films.length]` and calls that. `stepFilm()` is unchanged - it still just moves `filmIndex` by ±1, which slides the 2-film window forward/back one at a time (index,index+1 → index+1,index+2 → ...) rather than paging by 2, so `prev`/`next` still reach every fetched film, not just film pairs.
- **The screen canvas resolution was bumped from 512×342 to 900×600** - two narrower columns each need their own legible caption text, and this was an explicit "make sure it's legible" ask; a low-res canvas stretched over a smaller area would have looked fuzzy.
- **A nice side effect of narrower columns, not a deliberate tuning:** each column is much closer to square (~0.9 aspect) than the old full-width screen was (~1.5 aspect), which is a far better match for a portrait movie poster (~0.667) than before - the existing `Math.min(containScale * 1.45, coverScale)` blend formula was reused unchanged per column, and the geometry change alone means it now typically resolves to close to full cover-fit with only a modest, reasonable crop, rather than needing the multiplier retuned.
- **`drawCaptionBox()` now dynamically shrinks its font size (in a loop, down to a 14px floor) and word-wraps up to 2 lines** to keep a film's title+rating legible in a column roughly half the previous width - a fixed font size that worked full-width would either overflow or need squishing (illegible) in a narrower column.
- **`/api/letterboxd`'s `EAGER_COUNT` went from 1 to 2** - both default-visible posters (not just the first) need to be ready immediately, or the second column would flash an empty placeholder on first load. Response size grew from ~73KB to ~117KB accordingly - still far below the original ~356KB (all 5 posters) from before the load-time fix in take 6.
- Reused `wrapText()` (originally written for the desk note, see the take-8-era note-wrapping fix) and `resolveFilmThumb()`/`renderToken` (from take 6's lazy-poster-loading work) as-is from other parts of this same component - both are plain `function` declarations, hoisted within `initScene()`'s scope, so they're callable from code defined earlier in the file without reordering anything.
- **Fixed a related bug surfaced by testing, not requested but broken**: the note's `paintNote()` used a bare `fillText` per to-do item with no wrapping, so a longer `workingOn` entry (the user tried `'Making this not shitty'`) ran off the edge of the note's canvas and got clipped by the canvas boundary rather than wrapping. Added a small `wrapText()` word-wrap helper used for every item now - if `workingOn` in `now.astro` ever gets a long entry, it'll wrap onto multiple lines instead of overflowing invisibly.

**Now page, take 10 - rendering-quality pass, "production quality... as if for a business" (2026-09-23):** the scene worked but looked like a flat-shaded 3D mockup rather than a rendered product shot. This was explicitly a quality bar, not a specific ask, so the changes below are the concrete, mostly-standard three.js techniques that close that gap - all in `initScene()` in `DeskScene.astro` unless noted. **User flagged load time as a constraint before this started** (this page has a real history of load-time regressions - see takes 6 and earlier) - every change here was deliberately chosen to add ~0 network payload, confirmed by inspecting the build output, not assumed.
- **Tone mapping + explicit color space**: `renderer.toneMapping = THREE.ACESFilmicToneMapping`, `renderer.toneMappingExposure` (tuned to `0.95` after `1.15` washed the wall out too light/flat), `renderer.outputColorSpace = THREE.SRGBColorSpace`. This alone is most of the "looks like a real render" difference - three.js's default linear output clips highlights hard and reads as flat/plasticky regardless of material tuning. Every `CanvasTexture` used as a color map (wood, wall, floor, grille, screen, record, note - all of them) needs `texture.colorSpace = THREE.SRGBColorSpace` set explicitly once tone mapping is on, or colors render washed out/wrong; the pure-black contact-shadow gradient texture is the one exception left unset, since 0 maps to 0 in both spaces so it doesn't matter there.
- **An environment map, generated procedurally, not loaded from a file.** `scene.environment` was empty before, which means `metalness`/`roughness` on `MeshStandardMaterial` had nothing to actually reflect - brass, the platter rim, and the glass lid all looked like flat-shaded plastic no matter how those two properties were tuned, because there was no environment for them to pick up. Fixed with three.js's built-in `RoomEnvironment` (`three/addons/environments/RoomEnvironment.js`, dynamically imported) run through a `THREE.PMREMGenerator` at scene-init time - this is a tiny procedural in-scene generator (a handful of box meshes), not an external `.hdr` file (those commonly run several hundred KB–multiple MB and would have undone the load-time work from earlier takes). **Confirmed in the build output, not assumed**: the addon chunk is 2.2KB; the three.js core chunk is unchanged at 718KB. `envTexture.dispose()` was added to `dispose()` alongside everything else that already gets cleaned up there.
- **A second, dim, shadowless fill light** (`fill`, cool-toned, opposite side from `key`, no `castShadow`) - a single hard directional light left the far side of every object pitched black, which read as a cheap/unlit render; real product photography is essentially never lit with just one light for this exact reason.
- **Contact-shadow AO blobs** (`addContactShadow(x, z, radiusX, radiusZ, opacity)` - a small radial-gradient `CanvasTexture` on a `depthWrite:false` transparent plane, laid just above the desk surface) under the TV, record player, and lamp. A single directional light's shadow map doesn't capture the tight, soft darkening real objects get right where they touch a surface - without this, objects read as subtly floating even with real shadows already present. Cheap: one small texture per call, no extra render passes, disposed automatically since it's caught by the generic `scene.traverse()` cleanup in `dispose()` like everything else.
- **Material tuning now that there's an environment to reflect**: desk-top wood roughness `0.75 → 0.45` (subtle lacquer sheen), brass lamp `0.35/0.75 → 0.22/0.9` roughness/metalness, platter rim `0.35/0.5 → 0.22/0.75`, TV frame lip `0.4/0.4 → 0.28/0.65`, vinyl record faces gained `roughness: 0.3–0.35` (previously unset, which defaults to fully matte - real vinyl has a visible sheen). Values are hand-tuned by eye, not derived from anything - if a surface looks wrong, these are the numbers to adjust, and check `scene.environment` is actually populated before assuming a roughness/metalness change alone will fix a flat-looking metal or glass surface.
- **Shadow quality**: key light's shadow map doubled to 2048×2048, plus `shadow.bias`/`shadow.normalBias` tuned to avoid acne on the higher-res map.
- **A real lighting bug found by testing, not by inspection**: adding the environment map visibly brightened the wall/floor beyond what was intended (the hemisphere light and the new environment ambient were stacking), and separately the record-player side of the wall was noticeably brighter than the TV side. The first was fixed by halving the hemisphere light's intensity (`0.65 → 0.4`); the second turned out to be the `warmGlow` accent point light's falloff distance spilling onto the wall (`4 → 2.2`) rather than anything about the environment map itself - worth remembering that a point light's `distance` parameter affects more of the scene than just the object it's meant to accent, especially near a large flat backdrop like this wall.

A Shape lives in the XY plane and extrudes along +Z, which happens to line up exactly with the width/height/depth convention `BoxGeometry` already used everywhere in this file - swapping one call for the other needs no extra rotation. Cause: most of the cap's UV coordinates land outside 0-1, and with the default `ClampToEdgeWrapping`, out-of-range samples just repeat the texture's edge-pixel color - which for that texture is the wood-toned border stroke, exactly the flat brown seen. Fixed by rotating the geometry itself (`tonearmGeo.rotateX(Math.PI / 2)`) before building the mesh, which bakes the rotation into the vertex data and leaves `tonearm`'s own transform at identity - the correct approach whenever a rotated mesh will parent other objects.

## Critical gotchas (read before touching layout)

### 1. `main` is left-justified and capped — `.full-bleed` exists because of this

`main` (in `Layout.astro`) has `max-width: var(--page-width)` and **no `margin: auto`** — it's deliberately left-justified, not centered, per early user feedback. This means **any box that "fills its container" still stops at 1120px and leaves blank space on wider screens** — this bug was hit and fixed independently on the resume PDF viewer, the projects grid, the homepage hero, the About page's bio/photo row, the Now page, and the blog list, before a shared fix was made.

**Use the `.full-bleed` utility class** (defined in `global.css`) instead of re-deriving this. It's `width: 100vw; margin-left: calc(-1 * var(--space-5))` with a mobile breakpoint override — it cancels `main`'s own padding to reach the true viewport edge. Pair it with `padding-inline: var(--space-5)` (`var(--space-3)` below 480px) on the element or a child, to keep content edge-aligned with the rest of the page.

**Do not use the classic `left: 50%; margin-left: -50vw` full-bleed trick.** It assumes a *centered* parent and silently produces a broken negative-offset layout here. Confirmed broken twice before switching to the padding-cancellation approach.

### 2. `overflow-x: hidden` on `html`/`body` breaks the sticky header

Tried this as a blanket fix for a minor tooltip overflow. It silently broke `position: sticky` on the nav header (a real, documented CSS interaction: non-visible `overflow` on `html`/`body` changes the containing block used for sticky positioning). Reverted. **Fix overflow issues at their source** (e.g. reduce a tooltip's `max-width`), not with a global overflow hack.

### 3. Astro compiler quirk: literal `//`-prefixed text can vanish

A text node starting with `//` silently disappeared from compiled output when it was the last of several top-level children slotted into a component (reproduced with `TerminalWindow` — never fully root-caused, smells like a minifier treating generated JS as having a line comment). **Never hardcode a literal `// ` prefix in HTML text.** Use the `::before { content: "// "; }` pattern already established by `.kicker` and `.section-heading` instead.

### 4. (removed) The `.typewriter` heading animation no longer exists

The 2026-08-21 redesign dropped the CSS typing effect on page `h1`s along with the rest of the terminal chrome — headings are just `.page-title`/serif now. If you see a stray `class="typewriter"` or `style={`--steps: ...`}` on an `h1` anywhere, it's dead leftover markup from before the redesign and can be deleted (the CSS backing it is gone from `global.css`, so it's currently a silent no-op, not a rendering bug).

### 5. Client-side scripts need `astro:page-load`, not top-level code

`<ClientRouter />` (in `Layout.astro`) intercepts internal navigation and swaps page content without re-executing already-loaded scripts. Any page script that does work on load (data fetching, `setInterval`, `IntersectionObserver`) **must** run from an `astro:page-load` listener, not top-level module code, or it'll only ever run once per real browser session. Bit the Now page's Spotify/Letterboxd widgets — fixed by moving init into an `astro:page-load` handler with `clearInterval`-before-`setInterval` to avoid stacking timers on repeat visits. `src/scripts/reveal.ts` follows the same pattern.

### 6. Verifying with screenshots: two false-positive traps

- **`[data-reveal]` elements below the fold** won't show as visible in a `playwright screenshot --full-page` capture even with a generous `--wait-for-timeout` — the fullPage resize-and-capture doesn't reliably give the IntersectionObserver time to fire for content far down a tall page. Confirmed via a scripted `page.evaluate(() => window.scrollTo(...))` that the reveal fires correctly for real users. Don't treat "invisible in a fullPage screenshot" as a bug on its own.
- **Vite dev-server "504 Outdated Optimize Dep" console errors** are transient noise from rapid navigation right after a dev server (re)start — not a real bug. If seen, restart the dev server fresh and re-check before treating it as an issue. Never present in `npm run build` output.

### 7. Debugging visual issues: check for scoped-style specificity collisions first

Astro auto-appends a `data-astro-cid-*` attribute to every rule in a page's local `<style>` block, so even an unrelated generic selector (e.g. a local `p { color: ... }` meant for card text) can silently outrank a global class rule (`.kicker { color: ... }`) on any element matching both. This exact bug caused inconsistent kicker colors across pages before the global `.kicker` color was made consistent. If a shared class looks right in the CSS but wrong on specific pages, check the page's own scoped styles before assuming the shared rule is broken.

## Content authoring

```sh
npm run new-post -- "Title" "description"       # scaffolds src/content/blog/<slug>.md
npm run new-project -- "Title" "description"     # scaffolds src/content/projects/<slug>.md
```

(`scripts/new-content.mjs`.) Or just copy an existing `.md` file in `src/content/blog/` or `src/content/projects/` and edit it directly — it's plain frontmatter + Markdown, nothing generated is special. The two things people trip on doing it manually: forgetting to rename the file (filename = URL slug; reusing an existing filename overwrites that post instead of creating a new one), and forgetting to update `date:` (controls sort order, newest first).

Schema (`src/content.config.ts`), identical for both collections:
```yaml
---
title: "..."        # string, required
date: 2026-08-22      # YYYY-MM-DD, required
```
